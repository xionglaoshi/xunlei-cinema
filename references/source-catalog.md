# 可复用片源渠道资源库

## 目的和边界

`~/.codex/skills/xunlei-cinema/private/渠道资源库.json` 保存执行任务中已经验证过的“渠道 + 方法”经验，供后续检索排序和故障回退使用。它不替代当前搜索，也不保证链接永久有效；每次使用仍须核对当前影片、年份、版本和真实文件清单。

渠道和方法必须分开评价。例如“SeedHub 页面能找到线索”与“从页面复制磁力并在迅雷云盘解析出目标正片”是两条不同记录，不能只因为站点名相同就合并成功率。

## 记录字段

每条记录至少包含：

- `channel`：站点、搜索服务或本地工具名称；
- `method`：搜索关键词、入口页面、复制磁力、读取迅雷分享、资源预解析等具体方法；
- `link_types`：网页、迅雷分享、磁力、HTTP/HTTPS、FTP 或种子；
- `best_for`：适合电影、剧集、整季、全集、4K 或 1080p 等范围；
- `evidence_level`：`已保存并回读`、`已读取真实清单`、`页面列出`、`仅搜索线索`；
- `successes` / `failures`：成功和失败的可回查摘要，不写凭据；
- `last_verified_at`：最近一次验证时间；
- `status`：`active`、`degraded`、`blocked` 或 `unknown`；
- `notes`：访问限制、错片风险、清单上限和回退方法。

可选记录 `evidence_refs`，只放技能目录内的非敏感日志、报告或文件路径。不得保存密码、token、验证码、临时播放 URL、带用户身份的请求头或未经脱敏的剪贴板内容。

## 什么时候写入或更新

1. **新增成功记录**：渠道确实返回目标影片线索，并且至少完成原页/分享清单核对；若已提交保存，还要完成迅雷目标目录读回。将“页面列出”“已读取真实清单”“已保存并回读”分级记录，不能统称为成功下载。
2. **更新方法**：记录真正有效的入口和动作，例如“搜索片名+英文名+年份”“打开跳转页复制真实 magnet”“读取分享详情后按文件 ID 转存”。不要只记站点首页。
3. **记录负面结果**：错片、空结果、分享失效、跳转到其他网盘、限流、验证码、清单不完整和安全上限都写入 `failures` 或 `notes`，并降低当前状态；同一失败重复出现时注明次数和最近时间。
4. **定期降级**：长期未验证的记录不能继续以已验证优先；使用前看 `last_verified_at` 和当前状态。旧记录保留历史，避免把暂时失效误认为从未有效。
5. **任务收尾同步**：多片任务可先在内存中收集结果，统一去重后一次更新资源库；没有新增证据就不改写台账。渠道资源库的变化与影片库变化分开，不因普通云盘扫描自动刷新。

## 使用顺序

先按目标片型、链接类型和最近验证时间筛选 `active` 记录，再并行执行多个渠道方法；候选统一进入质量比较。资源库没有记录、记录状态为 `blocked`，或当前方法连续失败时，回到 `SKILL.md` 的多渠道搜索和浏览器兜底流程。资源库只能帮助排序，不能跳过当前证据核验。
