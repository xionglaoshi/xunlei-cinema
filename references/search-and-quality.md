# 搜索与质量筛查

## 搜索范围

检索顺序以 `SKILL.md` 为准：先用 `search_sources.py` 并行查本地 PanSou、Bing RSS、百度；缺少可信 4K 时用 Agent 网页搜索工具补 Google 等结果；最后用浏览器自动化打开原页补漏和核对。对准确片名、年份及别名分别尝试“迅雷下载”“磁力/种子”“4K/2160p/1080p”“thunder:///magnet:”等查询。扩大到资源站点或论坛搜索时，记录实际来源页面，避免只依赖搜索摘要。

候选类型：

- 迅雷云盘分享：`https://pan.xunlei.com/s/...`；用 PanSou 检查分享是否有效，再打开分享页核对目录和影片。
- 迅雷离线链接：`thunder://...`；用 `~/.codex/tools/xunlei-cinema/scripts/inspect_link.py` 还原封装内容，读取文件名、声明大小和哈希（如可解析）。这不验证远端文件仍可下载。
- 磁力：`magnet:?xt=...`；提取 info hash、显示名称和 tracker 数。磁力本身通常不包含种子清单/文件大小；不连接 DHT、不下载媒体时应标低置信度。
- `.torrent`：搜索到公开种子链接时记录原网页与链接。只有用户提供本地种子文件后才可运行 `inspect_link.py --torrent-file <文件>` 读取文件清单和体积；不得启动 BT 客户端下载内容。
- HTTP/HTTPS 视频直链：脚本识别常见视频扩展名（如 `.mkv`、`.mp4`、`.webm`），标为 `direct_url`；仍须核对来源页与影片信息。没有这些扩展名的真实下载接口可能需要浏览器兜底发现。
- FTP：只对公开、无需凭据的 FTP 目录做匿名列表尝试；不猜测密码、不扫描目录树。浏览器/urllib若不支持 FTP，则报告未核验。

默认运行：

```sh
~/.codex/tools/xunlei-cinema/scripts/start_pansou.sh
~/.codex/venv/bin/python3 ~/.codex/tools/xunlei-cinema/scripts/search_sources.py "黑鹰坠落" --year 2001 --alias "Black Hawk Down" --output ~/.codex/tools/xunlei-cinema/var/black-hawk.json
~/.codex/venv/bin/python3 ~/.codex/tools/xunlei-cinema/scripts/analyze_sources.py ~/.codex/tools/xunlei-cinema/var/black-hawk.json --runtime 144
# 回到启动 PanSou 的终端按 Ctrl-C 停止
```

联网检索会受网页引擎限流、地区和代理影响。`search_errors` 是本次失败渠道记录；脚本无结果时须继续网页搜索及浏览器兜底，不能直接反馈找不到。搜索脚本抓取有限数量的结果页 HTML，只解析链接，不下载视频、压缩包或种子文件。

## 相关性与假标题

先以影片名、年份、英文名、系列归属消歧。搜索聚合器可能把长帖标题关联到帖内多个链接，或把整组资源错配给每个链接。对每个候选：

1. 查看链接周边文字，必要时打开原帖；
2. 对云盘分享，检查分享状态、目录名、视频文件名和文件清单；
3. 比对发行年份/版本、时长、音轨字幕及后续作品，排除同名片、预告、花絮和剧集；
4. 将来源页面中的宣称与实际观察分开记录。

## 版本、片长与完整性闸口

完整性优先于分辨率、码率和体积评分。先核对中文/英文片名、年份及剪辑版，再查发行方、分级机构、豆瓣等公开片长并记录具体页面；区分院线版、加长版、导演剪辑版、未分级版与地区版。尽量选可靠的完整发行版；有更完整的正规剪辑版时优先列出，但须注明版本改变，不把“更长”直接等同“更完整”，也不凭时长差断言被阉割。

- **两种片长分开**：公开资料是版本基准；迅雷原文件媒体信息、对应文件 MediaInfo/ffprobe 才是文件实际片长。种子文件清单通常没有实际片长；发布者MediaInfo可作声明证据。未知不可用公开片长反填，不可因为体积合理就当完整。
- **同版比较**：容差暂设 `max(2分钟, 公开片长×1.5%)`，超出则复核；比同版短超过 `max(5分钟, 3%)` 标为疑似缺失/删减。偏长也查花絮/多片合集。地区差异、片尾和元数据错误均可能解释差异；只有有证据的24→25fps加速才校正，不能仅凭短约4%自动认定PAL版。
- **分碟**：单碟不是完整电影。先核对同版全部分碟、顺序和每碟实际片长，再合计；不能把花絮、样片或另一部影片的时长/体积一起相加。合集必须选定单部正片。
- **容量交叉检查**：用实际片长估算总码率，再用对应完整版本片长估算预期体积。片长异常本身阻止自动优选，即使文件很大或码率看似合理；总码率含音轨，仍不能代替视频码率。
- **输出与闸口**：逐项列公开片长及来源、候选实际片长及证据、剪辑版、时差和完整性状态。缺实际片长、版本未确认、公开资料冲突、缺碟或时长异常均不可列为已通过完整性的最终替代；保留候选供人工审议。片长吻合也只排除明显缺失，不保证逐镜头无删减。

`analyze_sources.py` 接受以下字段（版本名使用一致的标识即可）：

```json
{
  "edition": "extended",
  "preferred_edition": "extended",
  "file_runtime_minutes": 228.2,
  "runtime_evidence": "measured",
  "runtime_source": "对应文件的本地MediaInfo路径或迅雷文件ID证据",
  "runtime_references": [
    {"edition": "extended", "minutes": 228, "source": "实际查阅的公开版本页面URL"}
  ]
}
```

亦接受 `file_duration_seconds`。发布者参数填 `runtime_evidence: claimed`；`measured` 只用于实际读取对应文件/原文件接口。`--runtime` 仅作缺资料时的容量估算，不通过完整性闸口。输出 `quality.completeness`；只有 `runtime_consistent` 才通过此闸口，`selection_eligible` 同时保留原画质/有效性要求，`provisional_eligible` 用于继续展示尚待核验的质量候选。

分碟输入使用 `expected_part_count`、`parts_same_edition_confirmed: true` 及 `runtime_parts`（各项含 `part_number`、`minutes`、`source`、`evidence: measured`），序号必须连续齐全。确有速度转换证据时可填 `playback_speed_ratio`（25/24或25/23.976）与 `playback_speed_source`。以上字段由实际检索和读取填入，脚本不编造公开片长，也不自动下载媒体补参数。

## 画质和文件容量估算

文件名、网页标签或发布者说明里的“4K/2160p”“1080p”都是声明，不是视频实测。脚本用片长和宽松的常见码率范围估计大致体积，给出容量过小/相符等线索：

| 类型 | 估算视频码率范围 | 估算用途 |
|---|---:|---|
| 2160p 高码率重编码（当前偏好） | 25–45 Mbps | 优先选择的压制版本；音轨和封装另计 |
| 2160p 其他压制/WEB | 8–25 Mbps | 合理性参考，不代表当前优选 |
| 2160p Remux/原盘 | 35–80 Mbps | 高码率原盘或 Remux |
| 1080p 压制/WEB | 3–10 Mbps | 常见压制/WEB 版本 |
| 1080p Blu-ray | 8–22 Mbps | 高码率蓝光来源 |

粗算：媒体体积（GB）≈ 码率（Mbps）× 时长（小时）× 0.45，再给音轨、封装留余量。编码器、音轨数、HDR、帧率、压制质量都会显著改变大小；范围用于标出可疑的小体积标签，不能判定真 4K。例：约 2 小时、标注 4K、文件仅 2–3 GB，应显著降低置信度；同一时长 50 GB 原盘体积看起来合理，也仍需来源/目录信息支撑。

当前选片偏好为 **4K 高清压制版（重编码），视频码率 25–45 Mbps，常规片长文件略小于 30 GB；超过 150 分钟的长片允许大于 30 GB**。杜比、蓝光来源、MKV 偏好继续保留。可信 4K 内先选明确重编码版，再考虑 WEB/类型未知，Remux/原盘最后；不能只凭 HEVC/H.265 标记认定重编码。先通过影片身份、版本、片长完整性和链接闸口，再按可信 4K 优先、1080p 兜底分组，在组内比较评分。低置信度、失效或疑似样片不因关键词多而优先。

评分由可信度分和偏好分分别组成；关键词是声明，只增加偏好分，不证明真实画质：

| 独立偏好项 | 加分 |
|---|---:|
| 4K／2160p／UHD | +40 |
| 杜比：Dolby Vision／DoVi／DV，或 Atmos／TrueHD／DDP 等杜比音频标记 | +20 |
| 蓝光：BluRay／Blu-ray／蓝光／BDRip／UHD BD | +15 |
| MKV 格式 | +10；依据选定文件扩展名或明确格式字段，同类不重复加分 |
| 明确重编码 | +30；Remux/原盘 −30，类型未知或普通 WEB 0 |
| 视频码率 25–45 Mbps | 有来源的实测 +25、有来源的发布声明 +15；未知或区间外 0 |
| 片长适配容量 | `max(0, 20 − abs(GB − target))`；≤150分钟或片长未知暂以28GB为中心，>150分钟中心为 `28 × 分钟/150`；软偏好，不是大小门槛 |
| 标称 4K 且不足 10 GB | 偏好 −20，并结合片长另做容量可信度判断 |

四个偏好类别可叠加，同类同义词或重复出现不重复加分；杜比视界和杜比音频单独标记，但杜比类别最多 +20。HDR 不自动视为杜比，Remux 不自动视为蓝光。常规片长以约 25–30 GB 为软优选带；短片不必凑足体积，长片不为低于 30 GB 牺牲码率。超过 150 分钟时按片长和码率判断容量，超过 30 GB 不构成淘汰理由；不再按文件越大越优排序。体积偏好针对单部正片，不拿合集或整季总大小参与比较；缺少单文件容量则体积不加分。技术标签应优先从选定文件名及对应说明取得，不把整页其他版本的标签拼到同一候选上。

MKV 是封装格式偏好，只增加偏好分，不增加画质可信度。优先使用实际文件名，兼容大写 `.MKV`、已解码文件名和磁力显示名；仅页面提到其他 MKV 版本不加分。格式未知或 MP4 等其他格式为 0 分，仍可选择。

## 输出

每项至少含：影片匹配依据、链接类型与可点击链接、原始来源页、标题/上下文、分辨率声明、声明文件大小、容量预期（片长已知时）、链接状态、置信度和未验证项。建议把“链接有效”“资源属于该片”“分辨率真实”分成三个独立判断，不能互相代替。

### 码率证据与片长冲突

视频码率优先从对应文件的 MediaInfo/ffprobe 或发布者参数取得，并记录来源；脚本接受 `video_bitrate_mbps`、`bitrate_source`（可回查证据）及 `bitrate_evidence`（`measured` 或 `claimed`）。只有带来源才按视频码率加分，未知不等于不合格。不得将总码率冒充视频码率。

仅有大小与片长时，估算总码率 `GB × 8000 / (分钟 × 60)`，输出“估算总码率，包含音轨和封装”；不能凭此宣称满足视频码率 25–45 Mbps。视频本身的预期容量 `Mbps × 分钟 × 60 / 8000`，再加音轨和封装。例如150分钟25–45Mbps视频约28.1–50.6GB，169分钟约31.7–57.0GB。码率与略低于30GB无法同时满足时，保留两者的真实数值和取舍，不硬判小文件更优。片长未知先查片长；不得硬套30GB上限。
