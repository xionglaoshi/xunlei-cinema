# 搜索与质量筛查

## 搜索范围

检索顺序以 `SKILL.md` 为准：先用 `search_sources.py` 并行查本地 PanSou、Bing RSS、百度；缺少可信 4K 时用 Agent 网页搜索工具补 Google 等结果；最后用浏览器自动化打开原页补漏和核对。对准确片名、年份及别名分别尝试“迅雷下载”“磁力/种子”“4K/2160p/1080p”“thunder:///magnet:”等查询。扩大到资源站点或论坛搜索时，记录实际来源页面，避免只依赖搜索摘要。

候选类型：

- 迅雷云盘分享：`https://pan.xunlei.com/s/...`；用 PanSou 检查分享是否有效，再打开分享页核对目录和影片。
- 迅雷离线链接：`thunder://...`；用 `scripts/inspect_link.py` 还原封装内容，读取文件名、声明大小和哈希（如可解析）。这不验证远端文件仍可下载。
- 磁力：`magnet:?xt=...`；提取 info hash、显示名称和 tracker 数。磁力本身通常不包含种子清单/文件大小；不连接 DHT、不下载媒体时应标低置信度。
- `.torrent`：搜索到公开种子链接时记录原网页与链接。只有用户提供本地种子文件后才可运行 `inspect_link.py --torrent-file <文件>` 读取文件清单和体积；不得启动 BT 客户端下载内容。
- HTTP/HTTPS 视频直链：脚本识别常见视频扩展名（如 `.mkv`、`.mp4`、`.webm`），标为 `direct_url`；仍须核对来源页与影片信息。没有这些扩展名的真实下载接口可能需要浏览器兜底发现。
- FTP：只对公开、无需凭据的 FTP 目录做匿名列表尝试；不猜测密码、不扫描目录树。浏览器/urllib若不支持 FTP，则报告未核验。

默认运行：

```sh
scripts/start_pansou.sh
python3 scripts/search_sources.py "黑鹰坠落" --year 2001 --alias "Black Hawk Down" --output var/black-hawk.json
python3 scripts/analyze_sources.py var/black-hawk.json --runtime 144
# 回到启动 PanSou 的终端按 Ctrl-C 停止
```

联网检索会受网页引擎限流、地区和代理影响。`search_errors` 是本次失败渠道记录；脚本无结果时须继续网页搜索及浏览器兜底，不能直接反馈找不到。搜索脚本抓取有限数量的结果页 HTML，只解析链接，不下载视频、压缩包或种子文件。

## 相关性与假标题

先以影片名、年份、英文名、系列归属消歧。搜索聚合器可能把长帖标题关联到帖内多个链接，或把整组资源错配给每个链接。对每个候选：

1. 查看链接周边文字，必要时打开原帖；
2. 对云盘分享，检查分享状态、目录名、视频文件名和文件清单；
3. 比对发行年份/版本、时长、音轨字幕及后续作品，排除同名片、预告、花絮和剧集；
4. 将来源页面中的宣称与实际观察分开记录。

## 画质和文件容量估算

文件名、网页标签或发布者说明里的“4K/2160p”“1080p”都是声明，不是视频实测。脚本用片长和宽松的常见码率范围估计大致体积，给出容量过小/相符等线索：

| 类型 | 估算视频码率范围 | 估算用途 |
|---|---:|---|
| 2160p 压制/WEB | 8–25 Mbps | 高效率编码到高码率 WEB 版本 |
| 2160p Remux/原盘 | 35–80 Mbps | 高码率原盘或 Remux |
| 1080p 压制/WEB | 3–10 Mbps | 常见压制/WEB 版本 |
| 1080p Blu-ray | 8–22 Mbps | 高码率蓝光来源 |

粗算：媒体体积（GB）≈ 码率（Mbps）× 时长（小时）× 0.45，再给音轨、封装留余量。编码器、音轨数、HDR、帧率、压制质量都会显著改变大小；范围用于标出可疑的小体积标签，不能判定真 4K。例：约 2 小时、标注 4K、文件仅 2–3 GB，应显著降低置信度；同一时长 50 GB 原盘体积看起来合理，也仍需来源/目录信息支撑。

## 输出

每项至少含：影片匹配依据、链接类型与可点击链接、原始来源页、标题/上下文、分辨率声明、声明文件大小、容量预期（片长已知时）、链接状态、置信度和未验证项。建议把“链接有效”“资源属于该片”“分辨率真实”分成三个独立判断，不能互相代替。
