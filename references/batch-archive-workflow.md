# 多片、多季、多集归档工作流

用于一次处理多部影片、整季动画或全集剧集。目标是减少无谓串行，同时保持每个文件的可核验证据。

## 1. 先建立清单

- 固定中文名、英文名、年份、季数/集数和用户指定目标目录。
- 系列全集先列期望覆盖，例如第 1 季 11 集、第 2—9 季各 10 集；来源页“全集”不能替代清单。
- 预读目标目录，记录文件 ID、名称、字节数和父目录；同名但大小不同不能直接视为重复。

## 2. 检索并行，证据集中比较

有界并行查：

- 本地 PanSou/PanSearch；
- SeedHub/Cihub 等资源页；
- 百度、Bing/Google 和可读取原始网页；
- 其他公开渠道，以及迅雷分享、磁力和直接链接线索。

渠道无固定唯一优先级；不能因 SeedHub/Cihub 有结果而停止 PanSou、百度或其他渠道。候选须跨渠道去重并核对原页或分享清单。整合包按以下顺序选择：

1. 真实清单完整覆盖目标季/集，每个正片可识别；
2. 版本、分辨率、字幕/音轨和容量声明整体一致；
3. 无样片、海报、NFO、压缩包或错片混入；
4. 达到用户最低要求（如 1080p）时，可优先于多个零散候选；
5. 缺集就拆分分季或逐集，不混入错集。

## 3. 有界并行保存

- 检索和清单读取可并行；转存、离线和移动写入须有限并发。
- 每个分享按准确文件 ID 操作，不未经核对整目录转存。
- 同一来源先一次读清单，再筛选文件，避免重复读取分享状态。
- 区分任务创建、任务完成和目标目录读回，最后一项才算成功。
- 异步移动或转存返回任务 ID 后，进行有界等待和轮询；首次数量不足不等于失败。
- 若分享清单达到安全读取上限，优先按季或子目录拆分查询；不得为绕过限制而盲目转存整个分享。

## 4. 统一平铺和命名

用户说同一目录时不创建季子目录，文件名使用：

`中文简称第X季第Y集.English Title SXXEXX.年份.技术字段.扩展名`

约定：

- 中文无空格；季/集使用阿拉伯数字；英文 SXXEXX 可补两位；
- 用户指定简称优先，例如“爱死机”“瑞莫”；
- 英文放在中文后，保留来源已有 1080p/2160p、WEB-DL、BluRay、编码、HDR 和音轨；
- 泛名 `01.mkv` 必须结合分享路径、原页或期望集合映射；
- 不把网页宣传的 4K/高清写入没有文件证据的名称；
- 敏感词改名时缩短中文或英文，保留简称、季集、年份和技术字段，不重复转存。

## 5. 收尾验收

回读目标路径、总数、每季集数、名称、扩展名、大小和父目录；源目录移动任务也要确认。不把海报、NFO、RAR、样片或错季计入。报告区分“已保存并回读”“任务已创建未完成”“候选未核验”和“无可用来源”。
